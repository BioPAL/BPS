# 5. L1 Post-Processing

(sec:atbd-l1-sar-5-1)=
### 5.1 L1a/b Data Formatting

**Algorithm overview and rationale**

The scope of this step is to “transcode” the L1a and L1b products generated by the L1 Core Processing step from the L1 Processor internal format to the official BPS L1 Products format.

This format is defined and described in details in {rd}`26`. The main components of a L1 Product are:

- the SAR image file(s), including the SAR image binary raster data for all the four BIOMASS polarisations, organised in two Cloud Optimized GeoTIFF (COG) files, one for amplitude and one for phase (only for L1a products) components. These data are those provided in output by the Autofocus (see {sec}`4.11`) or by the Ground Projection (see {sec}`4.14`) step respectively in case of L1a or L1b product;
- the main annotation file, including the properties and characteristics of the measurement data or how the measurement data was generated, stored in a single XML file;
- the Look-Up Table (LUT) file, including those metadata being too voluminous to be coded efficiently in an XML file (i.e., Look-Up Tables) and requiring a binary NetCDF file. These additional information are provided in output by various L1 Processor steps, in particular:
    - RFI Mask, generated by RFI Mitigation step (see {sec}`4.1`);
    - Sigma-Nought and Gamma-Nought Maps, generated by Radiometric Corrections and Calibrations step (see {sec}`4.8`);
    - Faraday Rotation, Phase Screen, TEC, Range and Azimuth Shifts Maps, generated by Ionospheric Calibration step (see {sec}`4.10`);
    - Autofocus Phase Screen Map, generated by Autofocus step (see {sec}`4.11`);
    - Denoising Map, generated by Denoising step (see {sec}`4.13`);
    - Latitude, Longitude, Height, Incidence and Elevation Angles Maps, generated by Back-geocoding step (see {sec}`3.5`);

```{note}
LUTs annotated in output product are a decimated version of output data of the various L1 Processor steps. Decimation factors (range and azimuth) are configurable. Different decimation factors for the different LUT groups can be used;
```

- the orbit and attitude files, including orbit and attitude information in dedicated XML files. In principle these are the same auxiliary orbit and attitude files taken input by the L1 Processor, unless it performs any interpolation, extrapolation, … operation. In this case the modified orbit and attitude information are annotated in these two files;
- the quick-look and overlay files, including an averaged and decimated preview of the SAR image data set and information about its geographic coverage (see next section).

(sec:atbd-l1-sar-5-1-1)=
#### 5.1.1 Quick-look Generation

The quick-look is a lower resolution version of the SAR image included in each L1 product. The following rules and properties apply:

- for L1a products, quick-looks are a power detected, averaged and decimated version of the full SAR image;
- for L1b products, quick-looks are a squared, averaged and decimated version of the full SAR image.

BIOMASS products, being full-polarisation ones, contain only one quick-look image which is a combination of the imagery from all the four polarisation channels. This is done exploiting the three Red-Green-Blue (RGB) channels of the PNG image and the Pauli decomposition colour coding scheme for L1a products, i.e.:

- Red channel: $\left\vert HH-VV \right\vert$ (double bounce);
- Green channel: $\left\vert HV+VH \right\vert$ (volume scattering);
- Blue channel: $\left\vert HH+VV \right\vert$ (surface scattering).

and the Lexicographic one for L1b products, i.e.:

- Red channel: $\left\vert HH \right\vert$;
- Green channel: $\frac{1}{2}\sqrt{{HV}^2+{VH}^2}$;
- Blue channel: $\left\vert VV \right\vert$.

The quick-look images are produced by basic sample averaging and decimation, in both azimuth and range directions. The number of averaging samples in range and azimuth as well as the range and azimuth decimation factors are configurable parameters.

After this operation, each RGB channel values are normalized by a configurable absolute scaling factor, in order to have comparable results even on different scenes.
